# Embodied Infra v1：职责与范围

> 状态：草案 v0.2（已根据 EMOS 代码审查修订，见 [03-emos-capability-audit.md](03-emos-capability-audit.md)）
> 目标：v1 是**能和 EMOS 联调跑通的原型**，不追求功能完整。

## 1. 定位

Embodied Infra（下文简称 infra）是位于"具身多 agent 系统（EMAS，如 EMOS）"之下的一层**运行时基础设施**：

- 它**观测** EMAS 的执行过程（事件），
- **维护**一份世界状态与执行记忆，供 agent 查询，
- **监督**执行过程，发现错误后通过一组有限的**干预原语**介入，
- 并把以上全部过程**记录**下来，便于回放和后续评测。

分工原则：**infra 提供机制，EMAS 决定策略。** infra 判断"发生了什么、对不对"，并提供"介入的手段"；"任务怎么拆、谁来做、怎么重新规划"始终由 EMAS 决定。

## 2. v1 职责（做什么）

| # | 模块 | v1 内容 | 说明 |
|---|---|---|---|
| R1 | 注册与会话 | 一次运行 = 一个 session；每个 episode 开始时，EMAS 注册各 agent（id、本体类型、能力描述 resume、可用动作） | 不做运行中的动态增删 agent |
| R2 | 事件采集与追踪 | 接收 EMAS 上报的标准事件，写入 JSONL 追踪文件，支持离线回放 | 追踪文件同时作为 mock 的数据源 |
| R3 | 世界状态与记忆 | 根据事件维护：实体（物体/容器/目标点）的最新位置与状态、agent 状态（位置、手持物）、动作历史及结果 | v1 只用内存存储，持久化方案后续再选型 |
| R4 | 查询接口（北向） | 提供少量只读查询工具，供 EMAS 的 agent 以 function-call 的形式调用 | v1 只要求在 EMOS 讨论阶段接入 |
| R5 | 监工（规则） | 基于事件和世界状态做规则检查（见 §4） | LLM 监工不进 v1，只预留接口 |
| R6 | 干预（南向控制） | v1 只做三种：**动作闸门**（放行/拒绝/替换）、**注入消息**、**打断当前动作** | 重新规划（`request_replan`）列为可选，v1 不强制 |
| R7 | 配置开关 | 总开关 + 各模块开关；总开关关闭时，EMAS 的行为与原版完全一致 | 用于回归测试和后续消融 |

## 3. v1 不做什么（non-goals）

- **不做 agent 之间的通信与协作协议**（a2a、协商、任务分解、分配）：这是 EMAS 的职责。infra 只会**观测**到 agent 之间的消息。
- **不替 EMAS 规划**：监工不生成新的任务分配，只给出"错误 + 证据"，必要时请求 EMAS 自己重新规划。
- **不涉及底层控制**：导航、抓取等技能仍由仿真中的 oracle 技能执行。
- **不接真机**，不做跨进程/网络部署（v1 在进程内运行；接口按"以后可以拆到进程外"来设计）。
- **不做资源仲裁**（多机抢同一物体、空间冲突等）。
- **不做 LLM 监工**、不做多 episode 的长期记忆、不做向量检索。
- **不修改 EMOS 的环境难度**（视野裁剪、技能失败注入等属于 EMOS 侧的扩展，另行规划）。

## 4. v1 监工规则（初版清单）

| 规则 | 触发条件 | 依赖信息 | 默认处置 |
|---|---|---|---|
| `unknown_entity` | 动作参数中的实体不存在于本 episode | 实体表 | 闸门**拒绝**并注入提示（EMOS 中未知实体会直接让进程崩溃，见审查 F1） |
| `unknown_action` | 动作名不在该 agent 的动作空间中 | 注册信息 | 拒绝并注入提示 |
| `precondition` | 违反动作前置条件：例如已手持物体时 pick、未持有目标物体时 place | 世界状态 | 拒绝并注入提示 |
| `capability` | 本体不具备该能力：例如无机械臂的 agent 执行 pick | resume | 拒绝并注入提示 |
| `outcome_failure` | 动作结束后，动作语义表中的 `post` 条件不成立（例如 pick 结束了，手里却没有目标物体） | 语义表 + 快照 | 注入提示（告诉 agent 上一个动作实际上失败了） |
| `repeat_failure` | 同一 agent 对同一目标连续 N 次以失败或超时结束 | 动作历史 | 注入提示 |
| `idle_deadlock` | 所有 agent 同时处于 wait 状态，且任务尚未完成 | agent 状态 + 任务状态 | 打断 wait 并注入提示 |

"失败"的判定：动作结束后，infra 用适配器提供的**动作语义表**（接口文档 §3.3.1）中的 `post` 条件，对照下一条快照推断结果。`precondition`、`capability` 两条规则也由同一张表驱动。因此所有规则都不写死任何 EMAS 的动作名，这是 infra 可迁移性的基础。

## 5. v1 验收标准

1. **回归一致**：`infra.enabled=false` 时，同一个 episode 的动作序列和指标与原版 EMOS 一致（LLM 本身有随机性，比较时使用录制的轨迹或固定的 LLM 回复）。
2. **追踪完整**：`infra.enabled=true` 时，每个 episode 都产出符合 schema 的 JSONL 追踪，覆盖 §3 中全部必选事件。
3. **记忆可查**：EMOS 讨论阶段的 agent 能调用至少一个查询工具，并拿到正确结果。
4. **监工有效**：在 mock 和 EMOS 上，各至少有一种人为注入的错误（例如错误的目标名）能被发现、拦下并纠正，且 episode 不会崩溃。
5. **mock 可回放**：mock 适配器能回放 EMOS 录制的真实轨迹，infra 在 mock 上与在 EMOS 上得到的世界状态一致。

## 6. 版本演进（v1 之后，仅列方向）

- `request_replan` 与可重入的组讨论（EMOS 需要改造）
- 执行阶段的查询工具（需要修改 EMOS 的 `OpenAIModel`）
- LLM 监工、按信息来源（真值 / 观测）区分的监工
- 持久化存储与语义检索
- 拆分到进程外（gRPC 或 WebSocket）、真机适配器（ROS2）
